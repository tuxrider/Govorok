# Govorok — речь и чат в субтитрах на стриме

**Govorok** (от «говорить», «негромкая плавная речь») — локальный проект для стрима:
читает чат Twitch, **переводит иностранные сообщения на русский через API
нейросети**, а **твою речь распознаёт и ведёт субтитры** — всё это показывается
**панелью и оверлеем прямо внутри OBS** (Виды → Доки → Пользовательские доки
браузера / Браузер-источник). Переведённое сообщение выделяется рамкой акцентного цвета:
внутри оригинал и блок перевода с меткой языка (`EN → RU`).

```
┌──────────────────────────────────────────────────────────────┐
│ 14:02:11  MOD SUB  Viewer        #channel                    │
│ Let's go, this boss is insane Kappa                          │  ← обычное сообщение
├──────────────────────────────────────────────────────────────┤ ← рамка #a78bfa
│ 14:02:40  SUB  Another          #channel                     │
│ gg wp, that was close                                        │
│ ┃ 🌐 EN → RU                                                 │
│ ┃ Давай, этот босс просто безумный                           │  ← перевод
└──────────────────────────────────────────────────────────────┘
```

А `run.bat` открывает **окно настроек** — там всё управление ботом, а чата в окне нет:

## Что уже работает

* **Чат Twitch только в док-панели OBS** (и в режиме без окна). Окно бота — это
  настройки: каналы, док, перевод, Twitch, шрифт, смайлы, зрители, статистика, лог.
* **Перевод через LLM API** — любой OpenAI-совместимый endpoint: DeepSeek, OpenAI,
  OpenRouter, Groq, локальная Ollama/LM Studio. Модель сама определяет язык и
  возвращает строгий JSON `{"lang": "en", "translation": "…"}`.
* **Рамка вокруг переведённого сообщения** + вложенный блок с переводом.
* **Экономия запросов**: кэш переводов, пропуск кириллицы, `!команд`, ссылок и
  сообщений без слов, лимит запросов в минуту, ограничение параллельности.
* **Смайлы Twitch, BTTV, FFZ и 7TV** — картинками, с сохранением пропорций
  (широкие смайлы вроде `WideHard` не растягиваются). Бейджи (STREAMER/MOD/VIP/SUB),
  цвета ников, системные плашки (очистка чата, удаление сообщения, подписки).
* **Настройка шрифта чата** — семейство из установленных в системе (с поиском) и
  размер 9–40, живой предпросмотр; в доке применяется сразу, без перезагрузки страницы.
* **Вкладки дока**: «Чат», «Зрители», «Статистика» — с ответами в чат веткой,
  списком пишущих зрителей и расходом на API.
* **Команды и таймеры** — `!команды` с переменными, правами и кулдаунами, счётчики
  использований и напоминания раз в N минут с проверкой активности чата.
* **Субтитры со своего микрофона** — локальный faster-whisper, silero VAD (не
  пускает музыку и клики в распознавание) и фильтр неуверенного текста; три режима
  показа — только речь, только перевод или обе строки. GPU используется, если доступен.
* **Режим без окна** — `python main.py --dock`: тогда работает только бот и док,
  окно не открывается вообще.
* Все настройки — в окне, конфиг лежит в `config.json` рядом с `main.py`.

## Быстрый старт (Windows)

```powershell
cd D:\Project\Govorok          # папку можно называть как угодно: run.bat работает от своей
python -m venv .venv          #   папки, а данные живут в %APPDATA%\Govorok
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Либо просто запустите `run.bat` — он создаст окружение при первом запуске и откроет
окно настроек вместе с док-панелью.

### Переименование из BotTTV

Проект раньше назывался **BotTTV**. Данные (конфиг с ключами, кэш смайлов, счётчики
команд, скачанные веса faster-whisper) лежали в `%APPDATA%\BotTTV` — при первом запуске
`Govorok` переносит эту папку в `%APPDATA%\Govorok` одним `rename()`, ничего не
перекачивается и не теряется. Если папка занята другим процессом, перенос не удаётся —
приложение просто продолжит читать со старого места. Имя пакета тоже сменилось:
`botttv/` → `govorok/`, папка проекта — `D:\Project\botttv` → `D:\Project\Govorok`.
Вкладки браузера в OBS достаточно переоткрыть по новой ссылке
из окна настроек (имя дока в списке OBS — «Govorok»).

### 1. Ключ для перевода

В окне настроек, раздел «Перевод» → «Провайдер» → выберите из списка и вставьте API-ключ:

| Провайдер | Base URL | Пример модели |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| OpenRouter | `https://openrouter.ai/api/v1` | `google/gemini-2.0-flash-001` |
| Groq | `https://api.groq.com/openai/v1` | `llama-3.3-70b-versatile` |
| Ollama (локально, без интернета) | `http://localhost:11434/v1` | `qwen2.5:7b` |

Для локальной Ollama ключ можно оставить произвольным (`ollama`), главное — чтобы
сервер был запущен: `ollama serve`.

### 2. Канал, док и (опционально) право писать в чат

* Поле «Каналы Twitch» — логин канала, можно несколько через запятую: `shroud, dota2`.
* **Читать чат можно без токена.** Для отправки сообщений нужен OAuth-токен:
  [twitchtokengenerator.com](https://twitchtokengenerator.com) → *Bot Chat Token*,
  затем укажите ник бота и токен (`oauth:…`) в разделе «Twitch». Бот должен быть
  модератором канала либо канал должен разрешать ему писать.
* Ссылку на док берите в разделе «Док-панель OBS» кнопкой «Скопировать ссылку».

## Смайлы: Twitch + BTTV / FFZ / 7TV

Twitch отдаёт позиции только своих смайлов (тег `emotes`), поэтому сторонние ищутся
по словам сообщения — как это делают браузерные клиенты.

| Провайдер | Глобальные | Смайлы канала | Как получаем канал |
|---|---|---|---|
| BetterTTV | `/3/cached/emotes/global` | `/3/cached/users/twitch/{room_id}` | нужен числовой `room-id` |
| FrankerFaceZ | `/v1/set/global` (только `default_sets`) | `/v1/room/id/{room_id}` | `room-id`, иначе по логину |
| 7TV | `/v3/emote-sets/global` | `/v3/users/twitch/{room_id}` | нужен `room-id` (404 = у канала нет 7TV) |

* `room-id` приходит в тегах Twitch сразу после входа в канал (`ROOMSTATE`), так что
  смайлы канала догружаются в фоне и не тормозят чат.
* Приоритет при совпадении кодов: **смайлы канала важнее глобальных**, внутри одного
  уровня — BTTV → FFZ → 7TV.
* Всё кэшируется в `emotes_cache.json` (TTL по умолчанию 12 часов, ключ
  `emotes.cache_ttl_hours`), поэтому после перезапуска смайлы есть сразу, а без
  интернета чат всё равно читается.
* Смайлы канала грузятся один раз на канал; кнопка «Обновить смайлы» в настройках
  сбрасывает кэш, там же можно выключить любого провайдера.
* Если загрузка не удалась (7TV любит отдавать 429 при залпе запросов), пустой
  результат не считается кэшем: попытка повторится через полчаса, а после
  перезапуска — сразу. Настройки смайлов канала тоже обновляются по TTL.
* Битой или недоступной картинке ничего не стоит: смайл просто останется пустым
  местом, чат и перевод продолжат работать.

## Шрифт чата в доке

В окне настроек, раздел «Шрифт чата в док-панели»:

* **Семейство** — выпадающий список шрифтов, установленных в системе (на Windows
  читаются из реестра: 170+ семейств, начертания вида «Arial Bold» схлопываются в
  «Arial»). Список с поиском, можно ввести название вручную — например `Consolas`
  или `JetBrains Mono`, если он установлен.
* **Размер** — слайдер 9–40 px. От размера зависит и высота смайлов, поэтому
  строка чата остаётся ровной.
* **Предпросмотр** — сразу показывает, как будет выглядеть чат в доке.
* После «Сохранить настройки» шрифт **применяется в доке сразу**, без перезагрузки
  страницы: бот рассылает подписчикам новое значение. Ссылка для OBS тоже несёт
  `font=` и `size=`, поэтому свежедобавленный док откроется уже нужным шрифтом.
* «Сбросить шрифт» возвращает системный шрифт и 14 px.

Шрифт влияет только на чат в доке; само окно настроек и страница статистики остаются
системными. Если название шрифта не найдено, браузер молча возьмёт шрифт по
умолчанию — сломать док этим нельзя.

## Док-панель в OBS

Чат с переводом смотрится прямо внутри OBS — отдельным доком, без вывода на стрим.
Бот поднимает локальный сервер, OBS открывает его страницу в доке:

1. Запустите `run.bat` — откроется окно настроек, а в блоке «Док-панель OBS»
   появится `док запущен · клиентов: 0`.
2. Нажмите «Скопировать ссылку».
3. В OBS: **Виды → Доки → Пользовательские доки браузера** → имя `Govorok`,
   URL — скопированная ссылка.
4. Док можно перетащить в любое место окна OBS, он запоминается между запусками.

Что умеет док:

* три вкладки: **«Чат»**, **«Зрители»** и **«Статистика»** (выбор запоминается);
* бейджи, цвета ников, смайлы Twitch/BTTV/FFZ/7TV, рамка и блок перевода,
  системные плашки — всё как было в окне бота;
* переключатель «только перевод» (по умолчанию берётся из настроек, дальше
  запоминается в браузере дока);
* **ответы в чат прямо из дока** — строка ввода внизу (нужны ник бота и OAuth-токен);
* догоняет пропущенное: при подключении сразу получает историю последних сообщений
  вместе с их переводами;
* сам переподключается, если бот перезапустили, и показывает баннер «нет связи»;
* заголовок со счётчиком `переведено / всего` и статусом подключения к Twitch.

### Вкладка «Зрители»

Список тех, кто пишет в чат: ник в цвете Twitch, бейджи (mod/vip/sub), сколько
сообщений и как давно писал. Никаких текстов сообщений — только список. Есть поиск
по нику и фильтр «в чате».

**Про полный список зрителей — честно.** Twitch не отдаёт «кто сидит в чате»
просто так:

* легаси-эндпоинт `tmi.twitch.tv/group/user/<логин>/chatters` больше не работает —
  отдаёт `404` (проверено на живых каналах);
* события `JOIN`/`PART` приходят только авторизованным подключениям: анонимный
  `justinfan` получает `CAP * ACK :twitch.tv/membership`, но за 20 секунд активного
  чата — ноль `JOIN`/`PART`, а список `353` содержит только собственный ник
  ([IRC Concepts](https://dev.twitch.tv/docs/chat/irc/)).

Поэтому вкладка собирает зрителей из **активности в чате** — это работает всегда и
без токена. Если нужен и список молчащих зрителей, включите официальный
`GET /helix/chat/chatters`:

1. В `config.json` заполните `twitch.client_id` (Client-Id вашего приложения Twitch)
   и `twitch.nickname` / `twitch.oauth_token` — токен бота со scope
   `moderator:read:chatters`;
2. бот должен быть **модератором** канала.

Тогда в списке появятся и те, кто молчит (`молчат: N`), а в блоке «Сессия» будет
видно, сколько зрителей вернул Twitch. Если прав нет, вкладка честно напишет
причину («нужен Client-Id и токен модератора», «нужен модератор в канале и scope
moderator:read:chatters (403)») и продолжит работать на активности.

Настройки в `config.json` → `viewers`:

| Ключ | Смысл |
|---|---|
| `enabled` | собирать статистику по зрителям |
| `idle_minutes` | сколько минут без сообщений считать зрителя ушедшим |
| `max_users` | сколько зрителей отдавать странице дока |
| `fetch_chatters` | опрашивать официальный список (нужен `twitch.client_id` и токен) |
| `poll_seconds` | как часто опрашивать официальный список |

### Вкладка «Статистика»

Считается за текущую сессию (кнопка «Сбросить статистику» обнуляет):

* сообщения, переведено (с долей от всех), пропущено эвристиками, ошибки;
* **топ языков чата** с полосками долей — какие языки пишут зрители;
* **расход на API**: запросов к модели, взято из кэша, ошибок, токенов на входе и
  выходе, отправлено символов, среднее время ответа и деньги.

Чтобы появилась оценка в деньгах, задайте цены за 1M токенов в настройках
(⚙ → «Цена входа/выхода, за 1M токенов») или в `config.json`:
`llm.price_in_per_mtok`, `llm.price_out_per_mtok`, `llm.currency`. Если цены нули,
показываются только токены — так честнее, тарифы у провайдеров разные.

### Ответы в чат из дока

Внизу вкладки «Чат» — строка ответа. Работает, если в настройках заданы
**ник бота и OAuth-токен**; иначе поле неактивно с подсказкой. Отправка идёт через
того же клиента, что и в окне бота, поэтому лимиты Twitch (20 сообщений / 30 с)
соблюдаются, а своё сообщение потом приходит в чат как обычное.

**Ответ на конкретное сообщение:** нажмите на сообщение в чате — оно подсветится,
в строке появится `@ник`, а под ней полоска «↩ ответ <ник>» с кнопкой отмены.
Отправка уходит настоящей веткой Twitch: бот добавляет тег
`reply-parent-msg-id`, так что в чате это выглядит как обычный reply. Выделение
текста мышью клик не перехватывает.

**Своё сообщение бота видно в доке** — с бейджем `BOT` и зелёной рамкой:

Это не мелочь, а обход особенности Twitch: **IRC не возвращает соединению его
собственные сообщения** — вместо `PRIVMSG` приходит только `USERSTATE`
([IRC Concepts](https://dev.twitch.tv/docs/chat/irc/)). Поэтому бот сообщает о
своих отправках сам (`on_sent` в IRC-клиенте) и рассылает их в док локальным эхом.
Свои сообщения не переводятся и в счётчик сообщений чата не попадают — их число
видно отдельной строкой «отправлено ботом» на вкладке «Статистика».

Настройки в `config.json` → `dock`:

| Ключ | Смысл |
|---|---|
| `enabled` | поднимать сервер дока при запуске |
| `host`, `port` | где слушать; для OBS на другом ПК — `0.0.0.0` и токен |
| `token` | проверяется в ссылке; для нелокального адреса создаётся автоматически |
| `history` | сколько сообщений отдавать доку при подключении |
| `only_translated` | начальное состояние фильтра |

Параметры можно задавать и в ссылке:
`?limit=120&only=1&size=15&font=Consolas&header=0&tab=stats`
(`tab=stats` открывает док сразу на статистике).

### Бот без окна

Если окно настроек не нужно (например, OBS запускается вместе с системой), есть режим
только для дока:

```powershell
.\.venv\Scripts\python.exe main.py --dock              # чат и перевод только в док
.\.venv\Scripts\python.exe main.py --dock -c xqc --port 9000
```

Или просто `run-dock.bat`. В этом режиме бот печатает ссылку для OBS и работает
в консоли до Ctrl+C; окно Flet не открывается вообще.

## Команды и таймеры

Разделы «Команды» и «Таймеры» в окне настроек — бот отвечает на `!команды` в чате и
раз в N минут напоминает что-нибудь зрителям.

### Команды

У команды есть триггеры (можно несколько, регистр не важен), текст ответа, права,
кулдаун и переключатели «отвечать в чат» / «показывать в доке».

| Переменная | Что подставит |
|---|---|
| `{user}`, `{display}` | логин и ник автора |
| `{channel}` | канал |
| `{args}`, `{1}`, `{2}`, `{args.1}`, `{target}` | всё после триггера или отдельные слова |
| `{count}` | сколько раз команда срабатывала (счётчик живёт в `counters.json`) |
| `{date}`, `{time}` | дата и время |
| `{random:да\|нет\|может}` | случайный вариант из списка |
| `{uptime}`, `{game}`, `{title}`, `{viewers}` | из Helix, если заданы `client_id` и токен |

Права: `все`, `подписчики`, `модераторы`, `стример`. Кулдаун считается на каждого
зрителя отдельно, плюс есть общий трёхсекундный — чтобы десяток человек не вызвал
шторм ответов. Кнопка «Проверить ответ» показывает, что получится с подставленными
переменными, не отправляя ничего в чат.

Без `client_id` и токена переменные `{uptime}`, `{game}`, `{title}` и `{viewers}`
честно отдают «нет данных» — остальные работают всегда.

### Таймеры

Таймер отправляет сообщение раз в N минут. Строк может быть несколько (в поле они
разделяются `|`) — тогда бот чередует их случайно. Опция «только при активном чате»
держит таймер в тишине: сообщение уйдёт, только если за указанное окно набралось
минимум N сообщений.

Каждый ответ помечается чипом: `⚡ команда` или `⏱ таймер`. Ответы уходят в чат, если
заданы ник бота и OAuth-токен, и **всегда** видны в док-панели — так командами можно
пользоваться даже при анонимном чтении. Счётчики срабатываний видны в списках, а
общее число — на вкладке «Статистика» в доке («команд сработало», «таймеров отправлено»).

## Субтитры со своего микрофона

Пятая вкладка окна — «Субтитры»: речь с микрофона распознаётся **локально**
(faster-whisper), а текст показывается зрителям оверлеем-Браузер-источником в OBS.
Ничего не уходит в сеть, кроме скачивания модели и (по желанию) перевода второй строки.

Как это работает:

```
микрофон (100 мс блоки, копия буфера + усиление)
   → RMS-гейт (тишина)  → silero VAD (речь/не речь)  → faster-whisper
   → гейт качества (no_speech_prob, avg_logprob) → чистка текста → оверлей в OBS
```

* **Захват** — PortAudio отдаёт вид на живой буфер, поэтому блок копируется
  (`copy=True`) и очищается: значения вне [-1; 1] — это незаполненная память, а не
  звук, и такие блоки отбрасываются до VAD (счётчик «мусорных блоков» в статусе).
* **RMS-гейт** ведёт адаптивный шумовой пол и закрывает фразу после `silence_ms`
  тишины; абсолютный порог — 0.0018 (≈ −55 дБ), ниже него тишина в распознавание
  не уходит вообще.
* **silero VAD** (модель идёт в комплекте faster-whisper) отвечает на вопрос «речь
  ли это»: музыка, клики мыши и эхо не доходят до Whisper. Пороги 0.5 / 0.25 / 0.15
  с гистерезисом, доля речевых блоков проверяется при закрытии фразы.
* **Гейт качества** смотрит метаданные декодера: `no_speech_prob` и `avg_logprob` —
  так отсекаются «спокойная музыка» и «татататата» до того, как их увидят зрители.
* **Усиление входа** (1–8×) применяется к сигналу перед Whisper: спасает тихий
  капсюль, когда не хочется крутить системные ползунки.
* **Серая гипотеза** появляется на длинных фразах (раз в ~1.3 с, на GPU — в ~0.6 с),
  финальный текст — после закрытия фразы; повторы подряд не дублируются.
* **Режим показа** — выпадающий список «Что показывать»:
  | Режим | Что видит зритель | Запросы к API |
  |---|---|---|
  | `только речь` (ru) | оригинал, перевод не вызывается | 0 |
  | `речь + перевод` (both) | оригинал крупно, перевод строкой ниже | 1 на фразу |
  | `только перевод` (en) | только перевод: строка появляется, когда API ответил | 1 на фразу |

  В режиме `только перевод` промежуточная серая гипотеза остаётся на языке речи
  (иначе экран был бы пуст, пока идёт фраза), а финальная строка заменяется пакетом
  с `replace: true`. Если перевод не вышел или язык цели совпал с языком речи —
  показывается оригинал, зритель не увидит пустоту.
* **Перевод субтитров** идёт **принудительно**, мимо чатовой эвристики
  «Не переводить сообщения с кириллицей» — иначе русская речь отбраковывалась как
  «уже на русском». Для этого у субтитров свой экземпляр `Translator` со своим
  `target_lang`: язык перевода чата он не трогает, а запрос уходит отдельной задачей
  в цикл событий, поэтому медленный API не задерживает следующие субтитры. Язык цели
  («Язык перевода субтитров») можно не заполнять — тогда берётся язык перевода чата.
* Режим и язык применяются **на лету**: оверлей получает пакет `settings` и
  перерисовывается, перезапускать бота и OBS не нужно (смена режима перезапускает
  только движок распознавания).

### GPU: что нужно и как это находит бот

Боту нужна **CUDA 12 (cuBLAS)**, cuDNN для Whisper не требуется. Проверка идёт сама:

1. ищутся папки `C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12*\bin`
   (именно `v12`, потому что ctranslate2 4.x не умеет CUDA 13 — при этом
   `CUDA_PATH` может указывать на `v13.0`, и это не мешает);
2. найденные папки (а также `site-packages/nvidia/*/bin`) прописываются в `PATH`
   и `os.add_dll_directory` — ctranslate2 грузит `cublas64_12.dll` через
   `LoadLibrary`, а тот ищет DLL именно по `PATH`;
3. если `cublas64_12.dll` не найден — движок считает на CPU и пишет причину в лог;
   `device: auto` подхватит GPU сам, как только CUDA появится.

На этой машине подошёл уже установленный талкит `CUDA\v12.0`. Альтернатива без
талкита — `pip install nvidia-cublas-cu12` (библиотеки лягут в `site-packages/nvidia`,
бот их тоже видит). Переменная `GOVOROK_FORCE_CUDA=1` (старая `BOTTTV_FORCE_CUDA` тоже работает) заставляет попробовать CUDA
даже если проверка DLL ничего не нашла.

Модели качаются один раз сами при первом запуске; можно скачать заранее:

```powershell

```

### Микрофон и индикатор уровня

PortAudio показывает один микрофон несколько раз — в MME, DirectSound, WASAPI и
WDM-KS. В списке он теперь один: дубли склеиваются по железу (в WDM-KS имя
локализованное — «Микрофон (…)" вместо «Microphone (…)»), а API дописывается в
подписи только если он у устройства единственный.

При запуске бот перебирает API по очереди (WASAPI → WDM-KS → DirectSound → MME →
системный по умолчанию): не каждый из них принимает 16 кГц, а гнать поток через
ресемплинг нам не нужно. В статусе видно, какой вариант реально открылся, а если
сработал не первый — в логе будет строка «WASAPI не подошёл — беру DirectSound».

Под строкой статуса — **индикатор уровня микрофона**: зелёная полоска, обновляется
10 раз в секунду по логарифмической шкале (−70…−10 дБ), рядом текущий уровень в дБ.
Если полоска не дёргается вообще, а порог в статусе (например −45 дБ) выше твоего
уровня — звук до бота не доходит: проверь гейн в Windows, выбранный микрофон в
настройках или «Резать тишину».

### Детектор речи (silero) и почему субтитры могли «врать»

Энергетический порог сам по себе не понимает, **что** он пропустил: фоновая
музыка, стрекот клавиатуры и клики мыши громкие — и раньше уходили в распознавание,
а Whisper на не-речи уверенно додумывал текст («спокойная музыка», «татататата»).

Теперь цепочка из трёх фильтров:

1. **RMS** — дешёвый отсекатель тишины (шумовой пол + адаптивный порог).
2. **silero VAD** (модель `silero_vad_v6.onnx`, идёт в комплекте faster-whisper,
   считается на CPU за доли миллисекунды на блок) — отвечает на вопрос «речь ли
   это». Порог входа 0.5, удержания 0.25, «пробный» 0.15: тихо-громкий блок может
   открыть фразу, но `flush` её отбросит, если доля речевых блоков ниже
   «Мин. доли речи в фразе». Отброженные counted в статусе (`не-речь N`).
3. **гейт качества расшифровки** — метаданные декодера Whisper:
   `no_speech_prob` (модель сама говорит «здесь нет речи», по умолчанию отсекается
   выше 0.75) и `avg_logprob` (насколько уверенно подобран текст, по умолчанию ниже
   −1.05 отсекается). Плюс чёрный список типовых домыслов и фильтр «татататата»
   (один слог повторяется 3+ раза и больше 40 % текста).

Проверено на синтетике: 6 с музыки → **0 реплик и 0 субтитров**; та же музыка
фоном под голосом → речь распознаётся полностью.

Если silero мешает (например, шепчешь вдали от микрофона) — в поле
«Детектор речи» выбери «по громкости»: фильтрация не-речи выключится.

### Если субтитров нет

По порядку, каждая строка — то, что видно на вкладке «Субтитры»:

1. **«движок: остановлен»** — нажми «Слушать микрофон». Настройки сами движок не
   запускают (только сохранение при включённом флаге).
2. **«оверлеев 0»** — страница в OBS не подключена. Причины: в источнике остался
   адрес режима примерки (`?demo=1`), потерялся `token`, или источник выключен.
   Лечится кнопкой «Скопировать ссылку на оверлей» → вставить в источник заново.
   Док-панель в этом счётчике не учитывается — считаются только оверлеи.
3. **«вход: … · пик −69 дБ · порог −14 дБ»** — нажми «Проверить микрофон (3 с)» и
   говори: кнопка скажет прямым текстом, слышно тебя или тихо. Если «слишком тихо» —
   гейн в Windows, другой вход или «Резать тишину (VAD)» выключить.
4. **«VAD выкл»** — поток режется ровно по «Кусок аудио» секунд, без определения
   речи. На шумном микрофоне это рабочий вариант, но текст будет резаться по таймеру.
5. **«мусорных блоков N»** в статусе — PortAudio отдавал незаполненные
   буферы; блоки отбраковываются до VAD, но если N растёт, устройство/драйвер
   подкидывает мусор (на этой машине так вёл себя DirectSound, поэтому теперь
   первым пробуется MME).
6. **«перевод второй строки: → en · запросов 0 · готово 0»** — если запросов ноль,
   а поле «Переводить субтитры на» заполнено: субтитры используют тот же
   OpenAI-совместимый endpoint, что и чат, поэтому проверь `Перевод → Переводить чат`
   и API-ключ. Если запросы есть, а «готово» ноль — смотри строку лога
   `субтитры: перевод не вышел (…)` там будет причина от API.
7. **Лог внизу окна** теперь пишет `субтитры: реплика 1.8 c` и затем распознанный
   текст, а также `слишком тихо: …` от кнопки проверки — по нему видно, на каком
   шаге всё останавливается.
8. **«отброшено: не-речь N» растёт, а субтитров нет** — silero считает звук не-речью:
   тише фон (музыка/стрим на колонках), ближе к микрофону или «Детектор речи:
   по громкости».
9. **Правки в коде подхватываются только новым запуском.** Если окно висело
   открытым — закрой и запусти `run.bat` заново.

Ещё один капкан, который бот теперь обходит сам: у этого микрофона WASAPI и WDM-KS не
открываются на 16 кГц, а DirectSound отдаёт незаполненные буферы (значения вроде 9e33).
Движок перебирает API (MME → WASAPI → DirectSound → WDM-KS → системный), после
открытия 0.4 с проверяет, что в потоке настоящий звук, и при нулях или мусоре берёт
следующий — об этом пишет в лог.

### Память: когда модель грузится и как её отпустить

Модель поднимается **только при запуске движка** — ни при открытии окна, ни при
импорте модуля: `Recognizer` создаётся с `_model = None`, `WhisperModel`
импортируется внутри `ensure()`, silero — внутри `start()`. Замер на этой машине
(`tools\mem_probe.py`):

| Состояние | Модель в памяти | silero | пик RAM процесса | видеопамять (весь GPU) |
|---|---|---|---|---|
| субтитры выключены | нет | нет | ~61 МБ | ~1560 МБ (без нас) |
| субтитры включены, `small` | да | да | ~553 МБ | ~2370 МБ (+≈800) |
| субтитры включены, `medium` | да | да | ~559 МБ | ~3830 МБ (+≈2300) |

Когда субтитры **выключают** в настройках или по кнопке «Стоп» → «Отпустить память
модели», движок зовёт `unload_model()` из ctranslate2: у тебя освобождается ≈2 ГБ
VRAM (замерено: 3732 → 1745 МБ). Режим «сдвинуть в RAM» оставляет быстрый старт,
полная выгрузка — загрузку с нуля (≈2 с). Проверить у себя: `tools\unload_check.py`.

### Управление

* Кнопка «Слушать микрофон» / «Стоп» — запуск и остановка без перезапуска бота.
* Кнопка «Отпустить память модели» — выгружает весы из видеопамяти (полезно,
  если субтитры нужны не всё время стрима).
* Вкладка помнит настройки в конфиге; при сохранении движок перезапускается, только
  если менялись модель, устройство, язык, микрофон или порог тишины.
* Статус показывает `движок: слушаю · base · cpu/int8 · реплик N · субтитров N ·
  задержка N мс · уровень 0.123` — по уровню видно, доходит ли звук с микрофона.
* Режим без окна (`python main.py --dock`) тоже запускает субтитры, если они включены:
  один процесс на бота и на оверлей.

Что получается (`D:\Project\release\Govorok-<версия>-win-x64.zip`, ~139 МБ):

`response_format`, приоритеты смайлов, дисковый кэш, TTL, 404 по каналу, статистика,
команды дока, ответы веткой, то, что сообщение с переводом доезжает до страницы дока,
нарезку речи VAD'ом, гейт не-речи silero, отбраковку мусора PortAudio и режимы показа
субтитров. Часть проверок оверлея и JS страниц выполняется на Node.js (CI запускает их
отдельным шагом).

### Тестовые копии конфига не содержат секретов

`AppConfig` умеет отдавать дамп с выжатыми секретами — `redacted()` /
`save(path, redact=True)`: вместо `twitch.oauth_token`, `twitch.client_id`,
`llm.api_key` и `dock.token` пишется заглушка `<redacted>`, а сам объект
конфига не меняется (то есть `can_send` и «перевод готов» продолжают работать).

Зачем это нужно: selftest и `tools/mem_probe.py` кладут копию конфига в
`.selftest-tmp/`, чтобы не мешать рабочим настройкам, а окно настроек при тесте
сохраняет конфиг вообще по своему обычному пути. Поэтому в тестах стоит
`app.config_save_redacts = True` — любое сохранение из окна пишет заглушки, и
`selftest.py` отдельно проверяет, что в тестовой копии нет ни одного значения из
реального `%APPDATA%\Govorok\config.json`. Папка `.selftest-tmp/` в `.gitignore`,
так что второй слой защиты — она не уезжает в репозиторий.


## Настройки (`config.json`)

| Ключ | Смысл |
|---|---|
| `twitch.channels` | список каналов (строкой через запятую тоже можно) |
| `twitch.nickname`, `twitch.oauth_token` | нужны только для отправки сообщений |
| `llm.base_url`, `llm.api_key`, `llm.model` | провайдер перевода |
| `llm.max_concurrency` | сколько переводов одновременно (осторожно с лимитами) |
| `llm.max_requests_per_minute` | жёсткий потолок запросов в минуту |
| `llm.json_mode` | `response_format={"type":"json_object"}`; при ошибке 400 бот сам повторит без него |
| `llm.price_in_per_mtok`, `llm.price_out_per_mtok` | цены за 1M токенов для оценки расхода в доке (0 = не считать) |
| `translation.target_lang` | язык перевода (по умолчанию `ru`) |

| `translation.skip_commands` | не переводить `!команды` |

| `ui.font_family` | шрифт чата в доке; пусто = системный (например `Consolas`) |

| `emotes.cache_ttl_hours` | сколько часов держать смайлы в `emotes_cache.json` |
| `commands[]` | команды: `triggers`, `response`, `permission`, `cooldown`, `enabled` |
| `timers[]` | таймеры: `lines`, `interval_minutes`, `only_when_active`, `min_messages` |
| `stt.enabled`, `stt.model`, `stt.device`, `stt.compute_type` | субтитры: включены ли и чем считать (`medium`, `auto`, `float16`…) |
| `stt.language`, `stt.beam_size` | язык речи и ширина поиска декодера |

Файл `config.json` попадает в `.gitignore` — ключи и токен никуда не уезжают.

## Как это устроено

```
main.py                окно настроек на Flet; держит бота, док, оверлей и статистику
govorok/config.py      dataclass-конфиг + чтение/запись config.json, миграция папки данных
govorok/irc.py          IRC-клиент Twitch: парсер тегов, PING/PONG, авто-reconnect,
                       лимиты JOIN и отправки (20 сообщений / 30 с)
govorok/render.py       разбор сообщения на сегменты (текст + смайлы) для дока
govorok/dock.py         док для OBS: HTTP-страница + WebSocket-рассылка, история,
                       команды страницы (ответы, статистика, зрители), режим без окна
govorok/emotes.py       BTTV/FFZ/7TV: парсеры API, реестр по каналам, кэш на диске
govorok/fonts.py        список шрифтов системы для настройки шрифта чата
govorok/viewers.py      зрители: активность в чате + официальный список Helix
govorok/commands.py     команды и таймеры: переменные, права, кулдауны, счётчики
govorok/streaminfo.py   состояние стрима из Helix для {uptime}, {game}, {viewers}
govorok/stats.py        статистика сессии: языки, токены, оценка расхода API
govorok/stt.py          субтитры: захват микрофона, VAD, faster-whisper, очередь реплик
assets/subs/index.html оверлей субтитров для OBS (прозрачная страница + WebSocket)
govorok/translator.py   перевод через OpenAI-совместимый API: кэш, эвристики,
                       лимиты, ретраи
govorok/config.py       dataclass-конфиг + чтение/запись config.json
assets/dock/index.html страница док-панели (ванильный JS, без внешних зависимостей)
selftest.py            автотесты без GUI и без сети
```

Поток данных: `IRC → ChatMessage → смайлы и бейджи → WebSocket → страница дока`,
параллельно `очередь перевода → N воркеров → httpx → блок перевода в доке`.
Окно настроек в этом потоке не участвует — оно только конфигурирует и показывает счётчики.

## Известные ограничения

* Анонимное чтение не даёт полного списка зрителей: события `JOIN`/`PART` Twitch
  присылает только авторизованным подключениям, а легаси-эндпоинт
  `tmi.twitch.tv/.../chatters` больше не работает. Вкладка «Зрители» собирает тех,
  кто пишет; полный список — только через Helix с токеном модератора.
* Смайлы-«модификаторы» BTTV и zero-width смайлы 7TV рисуются как обычные картинки,
  а не накладываются поверх предыдущего смайла.
* Unicode-эмодзи (⭐, 😂) рисует системный шрифт — они не подменяются картинками.
* Переводится сообщение целиком, включая смайл-слова; для очень «шумных» чатов
  удобнее фильтр «Только переведённые».
* Без CUDA 12 субтитры считаются на CPU: `medium` там не успевает за речью
  (~3.4 с на фразу), живой вариант — `small` (~1.2 с) или `base` (~0.4 с).
* Субтитры идут по репликам, а не по словам: «караоке»-подсветки и
  word-level таймстемпов нет, серая гипотеза может менять формулировку.
* Микрофон читается напрямую, поэтому шумодав и гейт OBS к субтитрам не
  применяются — если микрофон ловит игру, лучше взять обработанное
  устройство (NVIDIA Broadcast, виртуальный кабель).

## Что можно добавить дальше

* Модерация из дока: удаление сообщений, таймауты (токен и канал связи уже есть).
* Субтитры по словам (karaoke-подсветка): таймстемпы на уровне слов вместо реплики целиком.
* Экспорт статистики, списка зрителей и транскрипта субтитров в CSV/SRT после стрима.
* Наложение BTTV-модификаторов и zero-width смайлов 7TV поверх соседнего смайла.
* Свои смайлы из файла (без провайдеров) и «избранное» для перевода.
* VK Video Live как второй источник чата (заготовка API лежит в `vendor/`).
* Сборка в один `.exe` (`flet build windows`) для запуска без Python.

## Структура репозитория

```
main.py                 окно настроек (Flet), держит бота, док, оверлей и движок субтитров
```

вне репозитория — в `%APPDATA%\Govorok` на Windows и в аналогах на macOS/Linux.
